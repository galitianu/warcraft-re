# MOV-0012: near-axial heading noise

**Question.** How does the east/west "heading noise" that footman-v3 could not model
([footman-v3 results](footman-v3-results.md#unmet-gate-and-next-experiment)) depend on
the start position modulo 1/64, the target, the Y = 0 frame boundary, the distance
and the travel direction?

**Reference.** WC3 1.29.2 (9231), x86 32-bit, `wc3-1.29.2-9231-x86`. Windows 11 Pro
26200 ARM64 VM with 4 logical processors and Allow Local Files absent. All seven
game/editor/MPQ hashes were reverified against the
[environment record](../oracle/environment/wc3-1.29.2-9231-x86.json) on 1 October 2026.

relative to the travel direction, and lateral offset is perpendicular to it.

Every east/west variant shows the noise, with variant-specific sequences. The ranges
of a, b and d coincide, but their per-callback values differ. The noise does not need
the Y = 0 frame boundary (d), and it appears westward too (f). Travel at 30° is quiet (e).

## Answer

The noise is deterministic float32 arithmetic, not a position-grid effect.
WC3's square root is biased high. For near-axial travel the cosine of the target
angle is therefore a few hundred ulps below 1, and `acos` of it is 0.3–0.4° off
axis. That angle depends on the exact bits of `dx`, so every start, target and distance
gives its own sequence. Off-axis directions such as 30° are well conditioned.
[footman-v4](footman-v4-model.md) implements this arithmetic with no
per-variant rule. It reproduces every recorded X, Y, facing and timer string of all
24 MOV-0012 runs. The exception is X/Y at five early callbacks per run, which read
one frame earlier than the sampling rule predicts
([results](footman-v4-results.md#sampling-order)).
