# MOV-0024: completion at an occupied point

Issue #41, P3: does a nearby blocked movement probe end a point order, irrespective
of the occupant's order state? Target: WC3 1.29.2 (9231) x86 on the selected
Windows 11 Pro ARM64 VM. This design is fixed before capture.

## Exact intervention and held-out layouts

Five v1 scenarios in `scenarios/MOV-0024/`, Player(0) hfoo, acquisition disabled,
existing flat Phase 0 map, individual point orders (never group orders), 20 ms
samples at callbacks 0–600. Creation/watch order and action order are file order;
callback 0 precedes actions. The unchanged library uses its 1000-second clock.

| Layout | Starts (x,y,facing), in creation order | Orders, in issue order at time zero | Discrimination |
|---|---|---|---|
| a | (-500,0,0); (500,0,180) | u0,u1 → (0,0) | head-on shared goal without a third unit |
| b | (-500,0,0); (0,-500,90) | u0,u1 → (0,0) | right-angle shared goal versus a |
| c | (-500,0,0); (0,0,0); (0,0,0) | u1 → (1000,0); u0 → (0,0) | goal occupant u1 retains a move while physically blocked by u2 |
| d | identical to c | u0 → (0,0) only | same occupancy with idle u1; isolates order state |
| e | (0,500,270); (0,-500,90); (500,0,180) | u0,u1,u2 → (0,0) | held-out three-way meeting, different from MOV-0023 |

c/d deliberately overlap the two destination occupants to hold one at the exact
point without extra units or terrain. This is an artificial isolation setup, not
normal group play. All initial SAMPLE positions must equal the specified starts
within 0.001. In c, require u1 still has move order and unchanged position while
u0 approaches/stops; otherwise the intervention is inconclusive, even if a trace
comparison passes. d must retain both occupants idle. Retain any setup failure;
never reinterpret it as the requested moving-versus-idle comparison. These checks
prevent spawn displacement or early completion from silently changing the question.
